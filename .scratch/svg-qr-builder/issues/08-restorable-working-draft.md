# 08: Восстанавливаемый рабочий черновик

**What to build:** Пользователь после перезагрузки возвращается к последнему рабочему черновику со всеми настройками, скриптом и изображением, а ошибка хранилища не уничтожает его работу.

**Blocked by:** 03 / Полная настройка геометрии QR-кода; 04 / Завершённое SVG-представление; 05 / Произвольный скрипт скругления; 06 / Центральное изображение с модульным вырезом.

**Status:** ready-for-agent

- [ ] Рабочий черновик хранит полную полезную нагрузку, ECL, размер, цвета, фон, тихую зону, геометрию, script source, image Data URL, процент и padding.
- [ ] Формат сохранения имеет явную версию и валидируется до применения.
- [ ] Изменения сохраняются в `localStorage` без заметной задержки интерфейса и восстанавливаются после повторного открытия страницы.
- [ ] Отсутствующий черновик создаётся из согласованного встроенного QR-профиля.
- [ ] Повреждённые, несовместимые или частично недопустимые данные не исполняют скрипт, не удаляют исходную запись и приводят к понятному восстанавливаемому состоянию.
- [ ] `QuotaExceededError` и другие ошибки записи показывают локализованное сообщение и не удаляют существующие QR-профили или сохранённый черновик.
- [ ] После неудачной записи текущий черновик остаётся полностью доступен в памяти, пока открыта страница.
- [ ] Интерфейс предлагает освободить место либо экспортировать данные, не выполняя автоматическое удаление.
- [ ] Производные ошибки генерации и статусы декодера в черновик не сохраняются.
- [ ] Разрешение импортированного скрипта хранится отдельно от его исходного текста.
- [ ] Vitest покрывает сериализацию, миграцию, валидацию, повреждение и ошибки quota.
- [ ] Testing Library и Playwright подтверждают восстановление полного черновика, включая изображение и скрипт, после перезагрузки.
- [ ] Все обязательные проверки исполняемого кода, сборки и пользовательского flow проходят.
